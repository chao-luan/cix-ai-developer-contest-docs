# Recover System

本文档用于在设备无法启动、系统异常或环境损坏时，按照固定顺序恢复设备。

## 1. 适用场景

- 设备无法进入系统。
- 系统启动后异常频繁。
- 图形界面无法进入。
- OS 镜像或 SDK 环境疑似损坏。
- 需要恢复到统一参赛环境。

## 2. 恢复思路

建议按照从低风险到高风险的顺序排查：

```text
检查供电和外设
→ 检查显示输出
→ 检查启动盘
→ 重启系统
→ 重刷 OS 镜像
→ 更新 BIOS
→ 更换硬件交叉验证
```

## 3. 快速检查

### 3.1 检查供电

确认：

- 电源适配器规格满足要求。
- Type-C 供电线连接稳定。
- 板卡状态灯正常。
- 风扇或散热器工作状态正常。

### 3.2 检查显示输出

确认：

- HDMI / DP 线连接正常。
- 显示器输入源选择正确。
- 启动过程中是否出现 BIOS / UEFI 画面。
- 是否可以进入 UEFI 设置界面。

### 3.3 检查启动盘

确认：

- NVMe SSD 安装到位。
- SSD 可以被其他设备识别。
- 系统镜像版本正确。
- 分区未被误删或破坏。

## 4. 系统镜像恢复

如果怀疑 OS 镜像损坏，请参考：

```{toctree}
:maxdepth: 1

reflash-os-image
```

## 5. BIOS 恢复或升级

如果设备无法进入系统，且怀疑 BIOS 异常，请参考：

```{toctree}
:maxdepth: 1

update-bios
```

## 6. 恢复后验证

恢复完成后建议执行：

```bash
uname -a
cat /etc/os-release
lsblk
```

如涉及 NPU SDK，还应检查：

```bash
ls -l /dev/aipu
pip3 list | grep libnoe
```

## 7. 仍无法恢复时

如果完成 OS 重刷和 BIOS 更新后仍无法启动，建议：

- 更换 NVMe SSD 交叉验证。
- 更换电源适配器。
- 更换显示器或显示线。
- 更换 U 盘重新制作 BIOS 更新盘。
- 记录现象、状态灯、串口日志或屏幕截图后反馈维护人员。
